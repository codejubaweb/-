## 2026-03-05 - Clickjacking and XSS Mitigation for Static Frontend-Only Single-Page Applications
**Vulnerability:** Static frontend-only single-page applications often lack a dynamic backend, which prevents serving custom HTTP response security headers (such as `Content-Security-Policy` and `X-Frame-Options`). This leaves the application susceptible to Cross-Site Scripting (XSS) and Clickjacking attacks when hosted on static sites platforms without header control.
**Learning:** Client-side fallback mitigations are necessary when custom HTTP headers cannot be set. A Content Security Policy can be delivered via a `<meta http-equiv="Content-Security-Policy">` tag, and Clickjacking protection can be established with a robust inline frame-busting stylesheet and script. However, injecting these directly into `index.html` during development can break Hot Module Replacement (HMR) and inline style injections.
**Prevention:** Use a custom Vite plugin during the production build step (`vite build`) to dynamically inject a highly restrictive CSP meta tag and an anti-clickjacking frame-busting script. This keeps the developer environment fully functional while ensuring the production build is highly secure by default.
