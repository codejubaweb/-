## 2026-03-05 - [Content Security Policy Implementation]
**Vulnerability:** Missing Content Security Policy (CSP) headers or meta tags in the frontend entry HTML. This leaves the portfolio application vulnerable to Cross-Site Scripting (XSS) and clickjacking attacks where malicious scripts could be loaded and executed from unauthorized third-party sources, or the site could be framed on malicious origins.
**Learning:** For static/single-page frontend applications without a dynamic backend server to inject CSP headers, a `<meta http-equiv="Content-Security-Policy">` tag must be embedded directly in `index.html`. The CSP must carefully allow required external assets like Google Fonts (`https://fonts.googleapis.com`, `https://fonts.gstatic.com`) and specific trusted media delivery domains (`https://lh3.googleusercontent.com`, `https://github.com`) while restricting script/style execution to `'self'` and `'unsafe-inline'` where necessary for framework and build tool hydration.
**Prevention:** Always verify and define explicit CSP rules for all external integrations. Ensure frame-ancestors is restricted (e.g., `'none'`) to prevent unauthorized clickjacking of the application page.
